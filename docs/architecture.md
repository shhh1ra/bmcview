# Архитектура

## Цель и рамки

Заменить штатный Java-клиент KVM Huawei iBMC настольным приложением для внутреннего использования
(небольшой ЦОД, ~10 человек).

- Платформы: Windows 10/11, macOS.
- Целевое оборудование: только Huawei RH1288 V3 с iBMC. Прошивка снята с поддержки и обновляться не будет,
  поэтому протокол считаем замороженным.
- **В объёме:** логин по HTTPS, видео, клавиатура, мышь (абсолютный режим), управление питанием,
  качество картинки, полноэкранный режим, индикаторы Num/Caps/Scroll, сохранённые хосты.
- **Вне объёма:** виртуальные носители (ISO/CD/floppy), ветка iMana (`com.kvmV1`), шасси с blade,
  резервный логин через IPMI, подпись и нотаризация, автообновление, низкоуровневый перехват
  клавиатуры ОС, хранение паролей (решение Р8).

## Слои

```
┌─────────────────────────────────────────────────────────┐
│ ui/  TypeScript + canvas                                │  отрисовка блоков, тулбар, хосты
├─────────────────────────────────────────────────────────┤
│ app/ Tauri v2                                           │  окно, IPC (бинарный канал для видео),
│                                                         │  HTTPS-логин, сетевой цикл сессии
├─────────────────────────────────────────────────────────┤
│ core/  протокол, крипто, видео, сессия                  │  без UI, сети и ОС
└─────────────────────────────────────────────────────────┘
```

## Решения

### Р1. Tauri v2 + ядро на Rust (2026-10-28)
Отказались от варианта «локальный сервер + системный браузер». На macOS нет гарантированного Chromium,
Safari не поддерживает Keyboard Lock, а локальный HTTP-порт — лишняя поверхность атаки.
Go + Wails отклонён: IPC Wails идёт через JSON, и для видео понадобился бы внутренний WebSocket.
У Tauri v2 есть бинарный IPC.

### Р2. Ядро без ввода-вывода
`core` принимает и возвращает байты и структуры, сокетов не открывает. Так протокол тестируется
на записанных дампах и на прогонах оригинального кода (см. [verification.md](verification.md))
без BMC и без окна.

### Р3. Видео декодируется в ядре, UI получает готовые блоки
Ядро держит пиксели всех блоков 64×64 и после кадра отдаёт список изменившихся. UI рисует каждый блок
в его позиции с отсечением по размеру экрана — так же, как оригинальный `ImagePane`.

Почему не декодировать JPEG в webview:
- копирование блоков («как слева», «как сверху») и наследование палитр требуют состояния блоков;
  держать его в одном месте проще;
- декодер целиком покрывается тестами в Rust, включая сверку с оригиналом;
- объём данных между ядром и UI ограничен пропускной способностью самого BMC.

### Р4. Точность порта важнее «красоты»
Где возможно, поведение повторяется побитово: формула цвета с усечением как в Java, знаковая арифметика
номеров кадров, правила запроса I-кадра. Осознанные отличия от оригинала:

| Где | Оригинал | Здесь | Почему |
|---|---|---|---|
| Ошибка посреди кадра | уже обновлённые блоки остаются | кадр применяется целиком или не применяется | предсказуемое состояние |
| Слот фрагмента пуст при сошедшейся сумме | NullPointerException роняет поток отрисовки | запрос I-кадра | живучесть |
| Битый JPEG-блок | блок без изображения, кадр показывается | ошибка кадра | явная диагностика |
| Сертификат BMC | принимается любой | запоминается отпечаток при первом подключении | защита от подмены |
| Имя пользователя в форме логина | не URL-кодируется | кодируется, как пароль | `&` или `=` в имени не ломают запрос |
| Кнопка «Обновить» | — | I_REQ сразу; ограничитель 500 мс только для сбоев видео | первое нажатие иначе ничего не отправляет |
| Обрыв TCP | `BladeReconnect` по reconnKey | то же, до 5 попыток через 2 с; 20 с без данных — обрыв | живучесть |

### Р6. CI на обеих ОС, релизы по тегу (2026-10-28)
Тесты, clippy и формат проверяются на `windows-latest` и `macos-latest` на каждый PR `dev` → `main`
(изначально — на каждый пуш в `main`, изменено в тот же день вместе с введением ветки `dev`).
Установщики собираются и публикуются только по тегу `v*` на `main`; тег с дефисом становится пре-релизом.
Сборка по каждому пушу отклонена из-за стоимости: репозиторий закрытый, а минуты macOS списываются ×10.
Свой раннер для Windows отклонён: все сборки — на чистых машинах GitHub.
Подробности — [releasing.md](releasing.md).

### Р5. Распространение без подписи
Внутренний инструмент: исключения Gatekeeper и SmartScreen выдаются вручную один раз.
Особых разрешений ОС приложению не нужно: перехвата клавиатуры нет (Р8).
### Р7. Сеть: rustls + ring, привязка сертификата (2026-10-29)
Логин по HTTPS идёт через `rustls` с криптопровайдером `ring`, а не через системный TLS. Так поведение
одинаковое на Windows и macOS, а сборка не требует cmake и NASM (их требует `aws-lc-rs`).
Сертификат BMC самоподписанный. При первом подключении запоминается его SHA-256
(`known_hosts.json` в каталоге данных приложения). Если сертификат сменился, рукопожатие обрывается
до отправки пароля, и UI показывает оба отпечатка; продолжить можно только явным действием.
Риск, который проверяли: rustls не поддерживает устаревшие наборы TLS 1.2 (CBC, обмен ключами RSA).
На первом подключении к RH1288 V3 (2026-10-29) рукопожатие прошло — прошивка предлагает современные наборы.

KVM-сокет — обычный TCP. Сессия из ядра (`core::session`) работает без ввода-вывода, сетевой цикл
(`app/src/console.rs`) только носит байты и таймеры. Видео идёт в UI бинарным каналом Tauri
(готовые RGBA-блоки 64×64), события — JSON-каналом.

### Р8. Системные сочетания — панелью, как в Java-консоли; пароли не храним (2026-10-29)
Сочетания вроде Win, Alt+Tab, Ctrl+Esc перехватывает ОС компьютера, на котором открыта консоль.
Вместо низкоуровневых хуков (`WH_KEYBOARD_LL`, `CGEventTap`) сделана панель «Клавиши», как
в оригинале: Ctrl+Shift, Ctrl+Esc, Ctrl+Alt+Del, Alt+Tab, Ctrl+Space, «Сбросить клавиатуру»
и своя комбинация до шести клавиш (например, Win+R). Отправка повторяет `CombineKeyListener`:
репорт комбинации, через 100 мс — текущее состояние клавиатуры.
Почему: так решил пользователь. Хуки — платформенный код с разрешением «Мониторинг ввода» на macOS,
которое без подписи слетает при каждом обновлении. Панель работает одинаково везде.
Пароли тоже не храним, как и оригинал: запоминаются только адрес и имя пользователя.
