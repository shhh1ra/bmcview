# Сборка и релизы

## Ветки

- **`dev`** — рабочая ветка. Сюда пушатся все изменения, проверка — локально на Windows
  (`cargo test --workspace`, `npm run tauri dev`). CI на пуш не запускается.
- **`main`** — всегда в рабочем состоянии. Изменения попадают сюда только через PR `dev` → `main`.
  Теги релизов ставятся только на `main`.
- PR мерджится **обычным merge commit**, не squash и не rebase. Тогда `dev` не расходится с `main`
  по истории и работу в `dev` можно продолжать без синхронизации.

Защита веток в закрытом репозитории на бесплатном плане недоступна. Правило «не мерджить с красным
CI» — договорённость: статус проверок виден в PR.

```bash
git switch dev
# ... изменения, локальная проверка ...
git push
gh pr create --base main --head dev --fill
# после зелёного CI
gh pr merge --merge
```

## CI (`.github/workflows/ci.yml`)

На каждый PR и по кнопке (Actions → CI → Run workflow), на `windows-latest` и `macos-latest`:

1. `npm ci` и `npm run build` — сборка UI (она встраивается в бинарник, без неё Rust-часть не компилируется);
2. `cargo fmt --all --check`;
3. `cargo clippy --workspace --all-targets --locked -- -D warnings`;
4. `cargo test --workspace --locked` — включая сверку с оригинальным клиентом.

На пуш CI не запускается: так macOS-раннер (×10) тратится один раз на пачку изменений в PR, а не на
каждый пуш в `dev`. Повторная проверка после мерджа в `main` тоже не нужна: проверено в PR.
Изменения только в `docs/` и `*.md` CI не запускают. Новый пуш в ветку PR отменяет устаревший прогон.

## Релизы (`.github/workflows/release.yml`)

Релиз собирается **по тегу `v*`**:

1. Черновик релиза. Проверяется, что тег совпадает с версией в `app/Cargo.toml` и `package.json`.
2. Сборки параллельно:
   - Windows: `.msi` (WiX) и `.exe` (NSIS);
   - macOS: `.dmg` и `.app.tar.gz`, universal (Apple Silicon + Intel), ad-hoc подпись.
3. Публикация. Если хоть одна сборка упала, релиз остаётся черновиком.

Тег с дефисом публикуется как **пре-релиз**: `v0.1.0-alpha.1`, `v0.2.0-rc.1`.
Тег без дефиса — обычный релиз: `v1.0.0`.

### Как выпустить версию

```bash
# 1. В dev поднять версию в app/Cargo.toml и package.json (одинаково, только X.Y.Z)
git commit -am "Версия 0.1.1"
git push
# 2. PR dev → main, дождаться зелёного CI, смерджить
# 3. Поставить тег на main и запушить его — дальше всё делает GitHub Actions
git switch main && git pull
git tag -a v0.1.1-alpha.1 -m "bmcview 0.1.1-alpha.1"
git push origin v0.1.1-alpha.1
```

Если сборка упала не из-за кода (например, GitHub не выдал macOS-раннер — так было с первым
пре-релизом), релиз остаётся черновиком. Достаточно перезапустить упавший джоб, публикация пройдёт сама:

```bash
gh run rerun <run-id> --failed
```

Номер внутри установщика — только `X.Y.Z`: WiX не принимает суффиксы вроде `-alpha.1`.
Поэтому каждый новый пре-релиз, который будут ставить поверх старого, поднимает хотя бы patch-версию.
Иначе установщик Windows посчитает его той же версией.

### Установка без подписи

Сборки не подписаны (решение Р5 в architecture.md):

- **Windows:** SmartScreen → «Подробнее» → «Выполнить в любом случае».
- **macOS:** первый запуск — правый клик по приложению → «Открыть»,
  либо `xattr -dr com.apple.quarantine /Applications/bmcview.app`.

## Стоимость Actions

Репозиторий закрытый: минуты на macOS-раннерах списываются ×10, на Windows ×2, на Linux ×1.
Бесплатный план — 2000 минут в месяц.

По первым прогонам (2026-10-28):

| Что | Реальных минут | Списывается |
|---|---|---|
| CI, Windows | ~10 | ~20 |
| CI, macOS | ~3 | ~30 |
| Релиз, Windows | ~11 | ~22 |
| Релиз, macOS universal | ~6 | ~60 |

Итого один PR — около 50 минут лимита, один релиз — около 80.
Свой раннер для Windows рассматривали и отклонили: сборка остаётся на GitHub, на чистых машинах.

## Локальная сборка

```bash
npm ci
npm run tauri dev     # разработка: окно + горячая перезагрузка UI
npm run tauri build   # установщики в target/release/bundle/
```

Иконки: `npm run icon` перерисовывает `assets/icon.png` (`tools/gen-icon.mjs`) и пересобирает набор
в `app/icons/`. Папки `android/` и `ios/`, которые создаёт `tauri icon`, не нужны — удалить.
